# Kowntaewook
팀명: APEX
본인 이름: 권태욱

2026.08.26

<일주일 동안 내가 만들어 낸 것>

APEX 디지털 포렌식 도구의 전체 기획과 코어 엔진 구조를 정리하고, FTK Imager와 Autopsy를 비교 대상으로 선정하여 벤치마크 시나리오와 검증 계획을 구체화했습니다. 또한 코어 엔진의 문서, JSON Schema, 실제 소스 코드 간 차이를 점검하고 수정했으며 검색, 보고서, AI 보조, 해시 검증, 민감정보 처리 등의 계약을 실제 동작과 맞추는 작업을 진행했습니다. Windows 환경에서 전체 테스트와 Ruff, mypy, Schema 검증을 수행해 오류가 없는 것을 확인했고, main과 feat/forensic-engine 브랜치도 동일한 상태로 정리했습니다. 이후 프론트엔드 담당자가 바로 개발할 수 있도록 현재 엔진의 기능과 제한사항, 화면별 구현 기준을 정리한 인수인계 문서도 제작했습니다.

<일주일 동안 겪었던 힘든 점, 극복했다면 해결 방법>

초기 기획 단계에서 생각했던 것보다 사용자 입장에서 필요한 추가 기능이 많아지면서 프로젝트의 범위가 계속 커지는 점이 가장 어려웠습니다. 또한 기능을 계속 추가하다 보니 문서와 Schema에는 정의되어 있지만 실제 코드와 조금씩 다른 부분이 생겨 이를 하나씩 확인해야 했습니다. 이를 해결하기 위해 기능을 단순히 추가하는 방식이 아니라 문서, Schema, 소스, 테스트를 서로 비교하면서 검증했고 실제 Windows 환경에서 전체 테스트를 반복해 문제가 발생하는 부분을 수정했습니다. 특히 민감정보 처리와 복호화 결과 Schema에서 발생한 오류도 테스트 결과를 분석하여 원인을 찾아 해결했습니다.

<내가 잘한 것과 더 잘할 수 있었는데 아쉬웠던 점>

단순히 기능을 많이 만드는 것에 그치지 않고, 구현된 기능이 실제로 동작하는지 테스트하고 문서와 Schema까지 일치시키려고 한 점은 잘했다고 생각합니다. 또한 코어 엔진과 프론트엔드, MCP가 서로 독립적으로 개발될 수 있도록 역할과 인터페이스를 정리하고, 다른 팀원이 참고할 수 있는 문서를 만든 점도 잘한 부분입니다. 다만 기획 초기에 사용자 요구사항과 추가 기능을 조금 더 폭넓게 예상하고 정리했더라면 중간에 설계를 수정하는 시간을 줄이고 프론트엔드 개발을 더 일찍 시작할 수 있었을 것 같아 아쉬움이 남습니다.

<다음주까지 해올 것>

현재 완성된 코어 엔진의 인터페이스와 인수인계 문서를 기준으로 프론트엔드 구현을 본격적으로 진행하고, MCP가 코어 엔진의 분석 결과와 Context를 사용할 수 있도록 연동 구조를 구체화할 계획입니다. Case, Evidence, Artifact, Search, Timeline 등 주요 화면을 우선 구현하고 실제 엔진 결과를 연결할 수 있는 구조를 만드는 것이 목표입니다. 또한 FTK Imager와 Autopsy를 대상으로 준비한 벤치마크 시나리오를 정리하고, 동일한 조건에서 성능과 기능을 비교할 수 있도록 실제 검증 준비도 진행할 예정입니다.
